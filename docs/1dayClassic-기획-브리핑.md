## 2. 기획 의도

### 2-1. 이 앱이 풀려는 것

알람은 매일 반드시 켜지는 화면이다. 그 자리를 광고나 공백으로 두는 대신 **읽을 것 한 쪽**을
놓는다. 사용자는 "공부하려고 앱을 여는" 것이 아니라, **이미 여는 화면에서 공부를 만난다.**

이 발상은 코드 곳곳에 그대로 남아 있다.

- 알람 화면의 버튼 이름이 '끄기'가 아니라 **'공부하기'**다. 알람을 끄는 것보다 공부로
  넘어가는 것이 이 앱의 목적이라 문구를 바꿨다는 기록이 스펙 문서에 있다.
- 잠금을 풀지 않은 상태에서도 오늘의 공부가 바로 뜬다(알라미와 같은 잠금화면 경험).
- 알람이 여는 책은 사용자가 서점에서 고른 책을 그대로 따라간다.

### 2-2. 화면을 관통하는 원칙

저장소의 주석은 결정마다 근거를 남기는 방식으로 쓰여 있고, 반복해서 나타나는 원칙이 있다.

| 원칙 | 어디에 나타나는가 |
|---|---|
| **하루에 한 쪽** | 하단 탭바를 없앴다 — "하루에 한 쪽이라는 화면에서 늘 떠 있는 탭바는 갈 곳이 많다는 인상을 준다" |
| **한 화면은 한 가지만 말한다** | 목차를 홈에서 떼어냈다("한 화면이 둘을 함께 말하면 어느 쪽이 주인공인지 흐려진다"). 마이페이지에서 '지금 읽는 책' 칸을 뺐다(홈이 이미 그 책을 펼쳐 두고 있어서) |
| **종이처럼 보일 것** | 그림자를 거의 쓰지 않고 hairline 선으로 구역을 나눈다 — "떠 있는 것이 아니라 종이 위에 인쇄된 것처럼" |
| **원본에 없는 것은 앱이 지어내지 않는다** | 『듣기의 말들』은 원본에 날짜가 없어 앱 어디에도 '1월 3일' 같은 표기가 나오지 않는다(`isDatedBook`) |
| **한 장에 한 덩이** | 카드 안에 스크롤을 두지 않는다 — "카드 안에서 또 스크롤하면 넘김과 스크롤이 같은 손짓을 두고 다툰다" |
| **읽는 글과 UI는 서체가 다르다** | 본문·인용은 을유1945(세리프), 버튼·라벨은 Pretendard |

### 2-3. 유유출판사와의 관계

- 데이터는 유유출판사 도서 **277권의 실제 카탈로그**(제목·저자·정가·ISBN·쪽수·표지·책 소개)이고,
  출처는 출판사 노션 페이지다(`data/uupress-catalog.json`, `scripts/fetch-uupress.mjs`).
- 초기 커밋 메시지가 "하루 클래식 publisher demo"다 — 출판사에 보여 주기 위한 데모로 시작했다.
- **(확인 필요)** 출판사와의 공식 제휴/계약 여부, 콘텐츠 사용 허락 범위, 이 앱이 출판사
  프로젝트인지 개인 제안용 프로토타입인지.

### 2-4. 타깃 사용자

- **(확인 필요)** 누구를 위해 만드는가. 코드에는 페르소나나 타깃 정의가 없다.
- 코드에서 유추만 가능한 것: 한국어 사용자, Android(iOS 미지원), 아침에 알람을 쓰는 사람,
  한자·한문·라틴어·명언 같은 인문 교양에 관심 있는 층.

## 3. 핵심 사용자 흐름

### 3-1. 첫 실행 (온보딩)

`app/onboarding.tsx` → `components/splash/SplashFlow.tsx`

```
인트로 → 질문 → 분야 고르기 → 책 고르기 → 알람 시각 정하기 → 권한 요청 → 홈(환영 시트)
```

- 요일은 묻지 않는다. 물음이 "매일 알림을 드릴까요?"라 답이 매일이라서, `EVERY_DAY`로 고정한다.
  평일만 받고 싶으면 알람 편집 화면에서 바꾼다.
- **권한을 먼저 묻고 그다음에 알람을 건다** — "알람을 거는 것은 결국 시스템에 부탁하는 일이라,
  부탁할 자격을 먼저 얻어 두는 편이 맞다." 거절해도 그냥 진행한다.
- **로그인은 건너뛴다.** MVP에 결제도 서버도 없어 계정으로 지킬 것이 없다. 로그인 시트는
  만들어 두었으나 미리보기(`app/splash-preview.tsx`)에서만 뜬다.
- 온보딩 완료 여부는 `AsyncStorage`의 `onboarded-v1` 하나로 본다. **읽기에 실패하면 '마쳤다'로
  간주한다** — 이미 쓰던 사람에게 온보딩을 다시 시키는 쪽이 더 나쁜 결과라서.

### 3-2. 매일 아침 (알람 → 공부)

```
알람 시각 → (잠금/화면꺼짐) 전체화면 알람 · (사용 중) 헤드업 알림
   → '공부하기' 누름
   → 잠금을 풀지 않은 채 오늘의 공부가 열림 (1dayclassic://today)
   → 카드를 좌우로 넘기며 읽기 → 퀴즈 → 리포트
```

- 여는 책은 `BookSelectionContext`의 선택된 책. 알람 딥링크는 `bookId`를 싣지 않으므로
  **그 기본값이 곧 알람이 여는 책**이다.
- 잠금 상태에서는 뒤로가기가 막히고, 홈 버튼을 누르면 앱이 아니라 잠금화면으로 나간다.
- 자동 재생은 하지 않기로 했다. `?autoplay=` 처리 코드는 남아 있지만 넘기는 곳이 없다.

### 3-3. 평소 (홈에서 읽기)

홈은 **어두운 화면 한가운데 지금 읽는 책 한 권이 서 있고, 그 아래 문 셋(목차 · 읽기 · 리포트)**이
있는 구조다. 어둡게 둔 이유는 "책장에서 책 한 권을 꺼내 든 장면"이기 때문.

가운데 읽기 버튼은 '오늘'이 아니라 **아직 안 읽은 첫 자리**를 연다. 버튼 위 말풍선이 무엇을
열게 되는지 말한다(`lib/progress.ts`의 `getReadPlan`).

| 상태 | 말풍선 문구 |
|---|---|
| 한 화도 못 끝냄 | 무료로 첫화보기 |
| 이어서 읽을 것이 있음 | 이어 읽기 : 제n화 |
| 무료 범위를 다 끝냄 | 1화부터 다시 읽기 |

**'끝냈다'의 기준**은 여는 것이 아니라 — 퀴즈를 다 풀었거나, '다음 화 읽기'를 눌렀거나,
마지막 장까지 닿았을 때다. 읽다 나온 화는 다음에도 그 화가 다시 열린다.

### 3-4. 읽기 화면 (카드 덱)

`components/lesson/CardDeckDetail.tsx` (2,237줄 — 이 앱에서 가장 큰 화면)

한 항목을 **여러 장의 카드**로 쪼개 좌우로 넘겨 읽는다. 장 구성은 `lib/card-pages.ts`가 만든다.

```
표지 장 → (인용 장) → 본문 장 여러 개 → 맺음 장 (마지막 화면 '마지막 페이지입니다')
```

- 본문은 한 장에 **200자 남짓**, 문장은 절대 중간에서 자르지 않는다.
- 넘김은 **책등(왼쪽 모서리)을 축으로 종이 한 장이 뒤집히는** 방식. 가로 ScrollView는 보이지
  않게 제스처만 맡고, 카드는 별도 층에서 직접 변형해 그린다. 새 라이브러리 없이 이미 쓰던
  reanimated만 쓴다.
- 낭독(TTS)을 지원한다. 문장 단위로 끊어 읽고 읽는 자리를 표시하며, 배경음악을 함께 깐다.
- 클래식 항목에는 **유튜브 재생기**가 카드 아래에 붙는다(높이 200px — 유튜브 약관이 정한 최소값).
- 책갈피(장 단위), 메모, 퀴즈가 이 화면에서 붙는다.

## 4. 콘텐츠 구조

### 4-1. 학습 가능한 책 10권 (`BookId`)

| BookId | 책 이름 | 저자 | 표제가 되는 것 | MVP |
|---|---|---|---|---|
| `classic` | 하루 클래식 공부 | 글릿 | 곡 제목 + 작곡가 | O |
| `latin` | 하루 라틴어 공부 | 김태권 | 라틴어 원문 + 발음 + 뜻 | O |
| `quote` | 하루 명언 공부 | 김영수 | 한자 원문 + 독음 + 뜻 | O |

| `liberal` | 하루 교양 공부 | 전성원 | 글 제목 | **X 제외** |
| `psychology` | 하루 심리 공부 | 신고은 | 글 제목 | O |
| `writing` | 하루 쓰기 공부 | 브라이언 로빈슨 | 글 제목 + 에피그래프 | O |
| `hanmun` | 하루 한문 공부 | 임자헌 | 한문 원문 + 토 + 번역 | O |

- **(확인 필요)** `liberal`(하루 교양 공부)만 MVP에서 뺀 이유. 코드 주석은 "아직 없다"고만 한다.

### 4-2. 항목 하나(`DailyLesson`)가 갖는 것

모든 책이 공유하는 공통부 + 책마다 다른 표제부로 나뉜다.

**공통부** — `id` · `date`(목차의 어느 칸에 앉을지 정하는 자리표) · `source`(출처) ·
`story`(본문 문단들, 낭독 대상) · `coverImage` · `unsplash`(사진+크레딧) · `imageKeyword` ·
`quiz` / `quizzes` · `featured`

**퀴즈** — 4지선다. 정답은 **1부터** 센다(콘텐츠를 개발자가 아닌 사람이 적으므로 화면의
"2번"과 데이터의 2가 같아야 한다). 『듣기의 말들』은 한 항목에 세 문제다.

### 4-3. 표지 그림을 무엇으로 채우는가 (`lib/cover.ts`)

우선순위를 한 곳에서만 정한다 — 화면마다 따로 판단하면 홈과 상세가 다른 표지를 그리게 되므로.

1. 항목에 `coverImage`가 있으면 그것 (사람이 고른 그림이 자동으로 가져온 것보다 앞선다)
2. 없고 책에 **표식**(symbol)이 있으면 검은 바탕에 표식 — 클래식은 높은음자리표, 듣기의 말들은 `) ) )`
3. 둘 다 없으면 **Unsplash 사진 + 사진가 크레딧** (가이드라인상 이름·프로필·Unsplash 링크를 함께 표시해야 한다)
4. 그마저 없으면 검은 바탕

### 4-4. 데이터 적재 현황 (365칸 중 실제로 채워진 항목 수)

| 책 | 항목 수 |
|---|---|
| 하루 명언 | 18 |
| 하루 라틴어 / 하루 쓰기 | 각 12 |
| 하루 심리 | 10 |
| 한자 / 한문 / 클래식 | 각 6 |
| 듣기의 말들 | 5 |
| 영어 교양 | 4 |
| 교양 | 1 |

각 책은 **365일 목차**로 그려지고, 원고가 없는 날은 **잠긴 자리표시**로 채운다. 진도·완독률
계산에서는 자리표시를 세지 않는다 — "읽을 수 없는 것을 총량에 넣으면 완독이 영영 오지 않는다."

### 4-5. 하루 서점 — 유유출판사 277권

`data/uupress-catalog.json` (노션에서 수집). 학습 콘텐츠가 있는 10권은 `bookId`로 이어지고,
나머지는 표지·서지·소개만 있는 전시용이다.

필터는 **시리즈**와 **분야** 두 축(`data/tag-taxonomy.json`). 출판사 쪽 '분야/시리즈' 필드가
한 칸에 섞여 들어와 앱이 둘로 갈라 준다. 시리즈 태그를 빠뜨린 책이 많아 **제목 끝으로 보완**하는
규칙도 둔다('…의 말들'로 끝나면 문장시리즈). '인문' 태그는 277권 중 193권(70%)에 붙어 있어
필터에서 제외했다.

## 6. 저장되는 것 (전부 로컬 AsyncStorage — 서버 없음)

| Context | 저장 키 | 무엇을 |

## 7. 알람 — 직접 만든 네이티브 모듈

`modules/alarm-clock/` (Kotlin, **Android 전용**)

Expo가 제공하는 알림으로는 "화면이 꺼져 있어도 켜지고, 잠금화면 위에 전체화면으로 뜨고,
누를 때까지 소리가 유지되는" 갤럭시 기본 시계 앱 수준의 경험을 만들 수 없어 직접 만들었다.

**구성** — `AlarmScheduler`(예약) · `AlarmReceiver` · `AlarmRingingService`(포그라운드 서비스,
소리) · `AlarmActivity`(전체화면 UI) · `AlarmFlowLifecycleListener`(잠금화면 플로우 제어)

**핵심 설계 결정**

| 항목 | 결정 | 근거 |
|---|---|---|
| `showWhenLocked` | **런타임 토글** (매니페스트 고정 아님) | 항상 켜면 알람과 무관하게 앱을 열 때도 잠금 위에 떠서, 폰을 주운 사람이 잠금 없이 내용을 다 본다 — 프라이버시 결함 |
| 화면 띄우는 길 | `setFullScreenIntent()` 하나 | 2026-09-04에 SYSTEM_ALERT_WINDOW 권한을 걷어냈다. 다른 앱을 쓰는 중이면 전체화면으로 덮지 않기로 해서 |
| 뒤로가기 차단 | 네이티브 `onBackPressed()` → true | JS가 느리거나 죽어도 뚫리지 않는다 |
| 알람음 | 기기 기본 알람음 | '기본음/커스텀' 선택지를 없앴다 — 커스텀이라 해 봐야 번들 음원 하나여서 고를 이유가 없었다 |
| 책 정보 전달 | 책 고를 때 **미리** 파일로 밀어 둠 | 알람이 울릴 때는 JS가 안 돌고 있다(앱 종료·재부팅 직후에도 울려야 한다) |

**알람 화면 색은 앱 본문과 다르다.** 본문 팔레트는 전부 밝은 배경을 전제로 잡혀 있어 어두운
사진 위에 얹히는 알람 화면에서는 쓸 수 없다. 그래서 violet 계열(`--violet-*`)과 `--night`를
별도로 두고, **앱 본문에는 쓰지 않는다.**

- **(확인 필요)** iOS 지원 계획. 현재 알람은 Android 전용이고, iOS에서는 이 앱의 핵심 흐름이
  성립하지 않는다.

## 8. 디자인 시스템

두 개의 층이 겹쳐 있다. 새 층으로 화면을 하나씩 옮기는 중이고, 옛 이름도 아직 살아 있다.

### 새 층 (`constants/theme.ts`) — "따뜻한 흰색 위의 검정 활자"

순백(#FFFFFF)도 찬 회색도 쓰지 않는다. 색의 97%가 무채색이다.

- **표면 3단** — `canvas #FDFCFC` → `card #F5F3F1` → `plate #EBE8E4`
  (+ 예외 하나: 뷰어/홈의 `#000000` — 몰입 화면이라 의도적으로 남긴 유일한 어두운 표면)
- **글자 4단** — `primary #000` / `strong #44403B` / `body #777169` / `muted #A59F97`
- **포인트 컬러** — `ember #FF4704`. **한 화면에 하나만** 얹는다("여러 곳이 동시에 주황이면
  어디를 보라는 말인지 사라진다"). `violet #0447FF`는 그림 안에서만.
- **퀴즈 정오답** — green/red. 디자인 문서에서 의도적으로 벗어난 자리다("정답·오답은 장식이
  아니라 기능이다"). 쓰는 자리는 퀴즈 보기와 해설로 한정.
- **서체** — 읽는 글은 을유1945, UI는 Pretendard, 인용 블록의 라틴 문자는 DM Serif Display.
  32px 이상 표제는 굵게 쓰지 않는다(Light 300) — "속삭임이 이 시스템의 서명".
- **자간** — 큰 글자는 당기고(-2%) 작은 글자는 벌린다(+1%). 방향이 반대인 것이 의도다.
- **여백** 4의 배수만 · **모서리** 알약과 20px 카드 · **그림자** 거의 없음, hairline 선으로 나눔

### 옛 층 (`global.css` + `Colors`/`Palette`/`Typography`)

베이지·브라운 계열의 따뜻한 팔레트(`--bg #faf6ee` 등). 아직 옮기지 않은 화면들이 쓴다.

> **작업 규칙** — 색·간격·서체는 **지정된 토큰만** 쓴다. 새 토큰이 필요하다고 느끼면
> 대개 기존 토큰을 잘못 고른 것이므로, 만들기 전에 반드시 확인받는다.

## 10. 수익 모델

- **(확인 필요)** 광고 도입 여부와 위치.

## 11. 기술 스택과 개발 제약

| 항목 | 값 |
|---|---|
| 프레임워크 | Expo SDK **57** · React Native 0.86 · React 19.2 · expo-router (typed routes) |
| 언어 | TypeScript 6.0 |
| 애니메이션 | react-native-reanimated 4.5 (새 라이브러리를 들이지 않는 것이 원칙) |
| 미디어 | expo-audio · expo-speech(TTS) · react-native-youtube-iframe |
| 저장 | AsyncStorage (로컬 전용) |
| 원격 자산 | Firebase Storage (커버 이미지, BGM 음원) |
| 패키지명 | `com.onedayalarm.app` |

**개발 시 반드시 지켜야 할 것**

1. **Expo Go로 실행되지 않는다.** 로컬 네이티브 모듈(`modules/alarm-clock`)이 있어
   **dev build 필수** — `expo run:android`, USB 연결 후 `adb reverse`.
2. **Expo SDK 57 문서를 확인하고 코드를 쓴다** — https://docs.expo.dev/versions/v57.0.0/
3. 새 코드를 쓰기 전에 **기존 구현을 먼저 검색**한다. `lib/`에 이미 있는 함수가 많다.
4. 검증 스크립트 — `npm run check:quizzes` · `check:tags` · `check:queries`
5. TTS는 `pitch`/`rate`를 **1.0으로 못박는다**. 시스템 음높이가 비정상인 기기(실측 186%)에서
   목소리가 짓눌려 들리기 때문.
6. `router.back()`은 Tabs 형제 화면 사이에서 기대대로 동작하지 않는다 → `router.replace` 사용.
